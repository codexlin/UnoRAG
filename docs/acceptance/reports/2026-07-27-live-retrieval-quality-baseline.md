### 为什么自动严格分比人工分低

以下答案语义正确，但旧 scorer 使用精确字符串包含，因此判为失败：

- `二十四个月` vs `24个月`
- `四位作者` vs `4位`
- `事故` vs `交通事故`
- `2026年Q2` vs `2026年第二季度`
- gold 没有显式 `key_facts` 时，旧逻辑错误地要求答案前 40 字整段匹配

自动严格分仍保留为可复现证据，但不能单独代表真实问答正确率。后续 gold
应支持显式关键事实、同义变体和数值归一化。

## 真实失败归因

### 1. 复杂跨页表格检索错库 — P0 质量问题

`crosstable-large.pdf` 的 4 条问题全部错误命中
`quote-big-80rows.docx`，目标文档排名为空：

- 汇总说明总项目数 / 总金额
- 75 条明细最大值 / 最小值
- 采购方式占比
- 序号 25 指定行

代表 trace：

- `95d06bdd-ca37-4dfa-911f-c5fda79359b3`
- `ce0aa886-5070-475c-803c-70d13f3cc6b4`

日志显示路由进入 `precise_table`，但检索到错误的 `table_id=t1`；
随后 `table_execute matched_count=0` 或 `table_unclear`。根因在
“表格候选文档选择 / table identity”，不是 LLM 文案。

### 2. 图表问题被错误短路到无关表格 — P0 质量问题

“图3硬件设备采购占比”错误命中报价表，并进入 `precise_table`：

- trace `dc88697f-adcd-4a47-9b80-14280cf00fe0`
- top score `0.553`
- `table_execute=fallback`、`matched_count=0`

系统目前没有可靠地区分“图片图表读取”与“结构化数据表查询”。

### 3. 同文档多段比较生成错误 — P1

“发生概率最高的风险”命中了正确文档，但回答成
“运营可持续性风险 50–60%”；gold 为
“组织协调风险 55–65%”：

- trace `8227b2ad-7b2d-482a-a5e8-233a7a26412f`
- route `fast`
- top score `0.631`
- 6 个 chunk 直接交给生成

这是同一文档多个风险段落需要全局比较时，fast 路径只依赖局部证据导致的
错误结论。

### 4. 扫描 PDF 在无 MinerU 时明确失败 — 已知能力边界

`scan-lowcontrast.pdf` 在 parsing 失败，4 条对应问题未执行。失败没有被伪装成
成功降级，符合当前严格 OCR 策略；若扫描件属于目标客户范围，MinerU 或其他
OCR 后端必须成为部署必选依赖。

### 5. 拒答语义与协议字段不一致 — P1

5 条库外问题均未编造；其中 4 条生成“资料未覆盖”，但响应仍带
`refused=false` 和多条低相关引用。只有低于阈值的一条进入
`weak_match` 并返回 `refused=true`。

代表 trace：

- 安全回答但协议未拒答：`53445361-050a-4333-ab96-986a3448f38f`
  （top score `0.511`）
- 正确协议拒答：`9723c0f4-a660-4f38-9ad9-4440bd778064`
  （top score `0.312`）

应让生成阶段的“资料未覆盖”结果回写标准拒答状态，清空或裁剪无关引用，
否则调用方无法可靠统计拒答率。

## 建议质量门槛

下一轮优化前先采用以下候选门槛，不把本轮分数直接包装成 PASS：

| 指标 | 建议门槛 |
|---|---:|
| 支持格式入库完成率 | `100%` |
| 目标文档 Recall@6 | `≥95%` |
| 文档级 MRR | `≥0.90` |
| 跨文档引用率 | `≤15%` |
| 人工问题级正确率 | `≥85%` |
| 库外问题安全不作答率 | `100%` |
| 拒答协议准确率 | `≥95%` |
| Ask p95 | `≤10s` |

## 下一步优先级

1. 修复表格候选文档绑定，禁止仅凭通用 `table_summary` 跨文档选中同名
   `table_id`。
2. 图表意图区分 image/chart 与 table，不能对图3/图4直接走表格短路。
3. 引用裁剪：优先目标文档，增加相对分差或最低分策略，减少跨文档噪声。
4. 把“资料未覆盖”标准化成 `refused=true`，并对外保持一致的
   `refuse_reason`。
5. 改造 gold scorer：显式关键事实、同义词/数值归一化、人工复核状态。
6. 启动 MinerU 后单独重跑扫描件 4 条，不与无 OCR 基线混为一谈。

跨文档表格错检索的完整问题复盘与修复设计见：
[`工程案例：表格问答为什么会选错文档`](../../case-studies/cross-document-table-retrieval.md)。
