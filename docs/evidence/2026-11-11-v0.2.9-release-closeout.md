## 香港真实邮件与账号

- 管理员在产品设置保存收件地址、启用通知、最低 `critical` 和恢复通知；刷新后配置仍在。
  地址来自当前 Workspace 的 PostgreSQL 设置，服务器环境仅负责服务商凭据、发件人及账号链接基址。
- 从页面提交一次测试邮件，队列第一次尝试成功，约 54 秒后服务商接受；Resend 查询返回 `delivered`。
  这证明服务商报告接收方邮件服务器接受，不证明人已看到邮件或一定进入主收件箱。
- 邀请、邮箱链接登录和重置使用 Resend 官方测试收件地址，不冒用真实用户。读取实际服务商邮件链接，
  经原生浏览器明确确认，完成邀请注册、已有账号链接登录、重置及新密码登录。
- 重置后旧 Session 返回 `401`；Viewer 读取工作区邮件设置返回 `403`。临时验收成员通过产品界面移除，
  未直接改库或删除审计。管理员会话已恢复。
- 凭据和一次性链接不进入 Git、公开报告或控制台输出；真实服务商验证不能继承为所有邮箱的送达保证。

## 结论与限制

### 2026-11-12 调查进展（不改写原结论）

保存的 point 被构造成两条/五条候选的受限派生重放，**不是历史完整五候选请求的精确重放**。
有效的两候选输入复现了模型在合法 JSON 中少抄 UUID 末尾一位、本地选择 ID 校验失败；
五候选输入当次通过。最初从公开 Citation DTO 构造的输入缺少内部 point ID，属于测试工具输入错误，
已弃用并增加输入 ID 校验，不计为产品失败证据。历史三次请求未保存中间模型输出，仍不能逐次确定原因。

候选修复让三个证据核验阶段使用请求局部短编号，严格映射回 canonical ID；没有更换模型、Parser、
检索策略、阈值或放宽引用校验。在香港独立、只读代码覆盖的一次性进程中，两种有效派生输入各执行三轮，
6/6 生成决策及 ID 还原通过；线上应用未被这次定向重放替换。该结果不等于 HTTP 完整问答或三轮矩阵通过，
v0.2.9 的 123/126、NO-GO 和草稿状态不变。

香港升级、邮件和浏览器专项已通过；完整稳定性总门禁 **NO-GO**，不发布正式 Release，不作客户生产签字。
旧版 25 文件业务矩阵、全量隔离、空安装、故障/破坏性恢复见
[v0.2.8 固定报告](https://github.com/codexlin/UnoRAG/blob/9ddb14432b75fd6d4dc7cbdc97e130c7e9f6ea4c/docs/evidence/2026-11-10-v0.2.8-release-closeout.md)，
本轮没有重跑这些完整套件，不继承旧 PASS。

- 当前为约 4 GB 内存的参考实例、受控 fixture、小样本；不能外推客户容量、通用正确率、SLA 或 RPO/RTO。
- 账号邮件为有界请求/Next `after`，非持久化账号邮件队列；进程中断可能需要重新申请。
  告警邮件使用独立持久化重试。默认 control 周期会让测试通知等待约一分钟。
- 质量门禁为确定性事实和引用契约，不替代语义复核、独立人工验收或 Ragas 忠实性评分。
- 未启用完整 Ops Stack、OIDC/SSO；对象内容恢复、客户硬件容量仍需单独验收。
