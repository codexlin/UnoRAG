## 确定性与产品链路

最终提交的主分支 CI 全绿，覆盖全历史密钥扫描、生产依赖审计、许可证和素材来源、TS core、真实
PostgreSQL/Qdrant/Redis 集成、应用测试、类型、Lint、生产构建和四镜像构建。

稳定 digest 在香港环境完成前向迁移、最小权限数据库角色检查、ACL reconcile 和产品冒烟：

`upload -> ask -> Public Retrieve/Ask -> service-key scope/revoke -> library isolation -> replace -> delete`

每一步使用公网 HTTPS、真实 PostgreSQL、COS、Qdrant、DBOS Worker 与模型 Provider；pilot smoke 最终
PASS，未使用 Fake index 或 Python 产品服务。

## 隔离与权限熔断

RC.21 精确提交在公网环境执行 29 项自动检查，全部 PASS，结束后自动删除测试 organization。覆盖：

- 同 organization 跨 Workspace、跨 organization、Session、Service Key Retrieve/Ask 零泄漏；
- library、document、archive、trace debug 的 IDOR 均按 404 失败关闭；
- 受限文档只向明确授权 principal 开放，owner 仍保留完整治理视图；
- viewer 的文档列表和知识库计数只统计可读文档；
- viewer 对受限文档的 versions、ACL、job、download 和 job list 元数据均不可见；
- replace/delete 完成后旧 marker 不可召回。

浏览器移动端会话复验了 viewer 页面：受限文档从 `2/2` 收敛为可读的 `1/1`，创建、上传和写设置入口
不可用，工作区策略控件只读。验收拓扑通过 Ops 镜像运行时保留宿主 UID/GID，报告和拓扑文件均为
`ubuntu:ubuntu`，可重复执行且不再产生 root-owned 产物。

## 故障、备份与回滚

- Qdrant 停止后 readiness 返回 503、`qdrant_unavailable`；启动后自动恢复 200。
- DBOS Worker 停止期间上传保持 `queued`，恢复后自动进入 embedding 并完成；后续 Ask、替换和删除通过。
- RC.21 成功回滚至 RC.20，再前滚至 RC.21；两次均排空旧 DBOS application version，数据库只前向迁移。
- 稳定镜像升级后再次执行完整 pilot smoke 并通过。
- 升级前备份包含 PostgreSQL、DBOS system DB、Qdrant 冷备与 COS 远端边界记录；全部 SHA-256 校验通过，
  SQL/custom dump/tar 产物可解析。未在当前在线实例执行破坏性原地 restore。

最终 lifecycle inspect 为 dead、stuck、deleting、cleanup error、pending ACL projection 和 tombstone 全 0。

## 适用范围与遗留风险

本报告支持 `v0.1.0` 在 UnoRAG-HK 单机参考拓扑作为稳定私有部署版本运行。它不证明多区域 active-active、
公网共享多租户 SaaS、持续峰值 soak、任意客户语料或任意模型 Provider 的容量。OIDC/SCIM、Helm
NetworkPolicy/PDB/HPA、用户组管理 UI、ChartIR 和公共文档生命周期 API 仍是后续能力；客户生产环境仍须
根据自己的身份、容量、备份和责任边界重新签署 Go/No-Go。
