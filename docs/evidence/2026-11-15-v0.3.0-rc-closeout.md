## 真实浏览器发现、修复与复验

RC1 零 mock 浏览器测试发现：新建库成功后，对话框先关闭，列表刷新完成后才选中新库；
在窗口期间立即上传会写入旧库。通过网络请求目标确认错库，不将其归为单纯等待超时。
误投的 fixture 经过文件名、创建时间和下载内容哈希核实，再通过正常删除生命周期清理。

PR #240 在关闭编辑器前，将已确认创建结果写入当前作用域缓存并选中；取消旧请求，创建后的刷新失败
不再把成功创建当失败。保存期间上传按钮和处理函数均拦截，后台刷新失败仍明确显示。
旧 RC1 的桌面/移动回归均失败；修复后含旧响应迟到的专项重复 8/8，实际校验上传请求只能提交到新库，
不只检查标题。独立代码 review 无确定性缺陷，要求补充的迟到请求覆盖已完成。

RC2 零 mock 真实浏览器完整链路 **PASS**：真实登录、UI 建库、立即上传、异步 ready、真实 SSE 答案、
剪贴板及复制确认、引用 HoverCard、来源面板、主题切换及 390×844 移动布局无横向溢出。
链路 UI 的用量与运维请求持久化记录逐项相等：输入 2899、输出 131、合计 **3030 Token**，3 次已上报 LLM
调用；不含 Embedding/Rerank，不将 Token 当作费用。测试库清理通过，未发现页面脚本错误。

  后续断言与 teardown 交错，不能将它们计为有效通过，也不能把空白失败附件当作会话丢失的证据。
