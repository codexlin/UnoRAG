## 1. 变更与问题归因

本版不改变检索、模型、ParserProvider、数据库 schema 或公共 API，只修复两类边界：

| 问题 | 修复前 | 修复后与证据 |
|---|---|---|
| #199 长回答的移动端显示 | 无断点正文、链接和行内代码可能越出回答容器；代码块在 `code` 层处理会遗漏无语言标签的 fence，并产生嵌套 `pre` | PR #200：容器允许收缩与任意必要换行；`pre` 层统一呈现代码块，保留横向滚动、复制和原文；不改生成内容 |
| #197 ACR 错误不可诊断 | `set -e` 在捕获 push 输出的赋值失败时退出，来不及打印 Registry 错误 | PR #201：显式保存退出码、脱敏输出后原码失败；超时仍为 124，不继续推送或生成失败目标的 digest |
| 当次 ACR OCI artifact 不兼容 | 诊断候选真实返回 `unknown manifest class for application/vnd.oci.empty.v1+json` | PR #203：`docker push --platform linux/amd64` 只推运行时 manifest；稳定流水线四个 ACR 镜像推送、签名和验证均通过 |

`pull --platform` 后本地仍可能保留带 attestation 的 OCI index，不能仅凭 pull 参数假定 push 是单平台。
Docker 明确说明 [push 的 `--platform` 语义](https://docs.docker.com/reference/cli/docker/image/push/)：
只推指定平台，不推 image index 或其中的 attestation。GHCR 仍保留规范 SBOM/provenance；
ACR 是有签名的运行时分发镜像，不宣称包含完整 provenance。两端 digest 因 index/runtime manifest
不同而不同，不能据此判定代码不一致。

失败诊断候选 [42165842625](https://github.com/codexlin/UnoRAG/actions/runs/42165842625) 使用 `7b45c8b`，
没有部署、没有作为 Release 资产。它证明本次 artifact 错误，不足以反推最早 `v0.2.4` 推送失败的根因。
脱敏保留原退出码的测试先复现旧代码失败；平台回归在加参数前 9/10、之后 10/10，不靠复制一份 Bash 实现测试。

## 5. 结论与保留边界

本报告只证明指定提交、模型/ParserProvider 配置、七份代表文件和香港参考拓扑，不是所有 PDF、
百万级语料、任意网络和多副本部署认证。移动测试是 Chromium 设备模拟，不等于 iPhone/Safari 实机认证。

- [#193](https://github.com/codexlin/UnoRAG/issues/193)：历史单次 Qdrant 失败缺少原始关联证据，根因仍未知；
  可控故障的诊断与恢复不能替代历史归因。
- [#202](https://github.com/codexlin/UnoRAG/issues/202)：可选离线 Ragas/DiskCache 工具存在尚无补丁版本的
  advisory；保留风险跟踪，不宣称已修复。它们位于 `scripts/evaluation`，四个产品镜像不安装该 Python 环境。
- 本轮不扩展 OIDC/SSO、ChartIR、Helm 生产加固或完整 Ops Stack。

Release 交付单元为两个签名 manifest、本报告与 `CHECKSUMS.sha256`。运行时仍固定于 `e749e2d`；
文档合并后的 main 只增加说明，不冒充新镜像构建。下一步是小范围真实用户试用与失败样本回归，
不是继续扩展框架、服务或可选观测组件。
