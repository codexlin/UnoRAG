升级前健康版本为 `0.1.0`。维护窗口备份包含 PostgreSQL plain dump、DBOS system custom dump、Qdrant
冷备和 COS 远端存储边界记录，五项 SHA-256 全部通过；本次未执行破坏性 restore。

升级先确认旧 DBOS application version 的应用任务和系统 workflow 均为 `active=0`，再停止旧
Web/Worker。前向迁移 `0023`、最小权限数据库角色复验、ACL reconcile 和新 DBOS Worker/Control
启动均成功。升级后生命周期巡检为：

- dead、stuck、deleting、cleanup error：0；
- pending ACL projection、过期或阻塞 tombstone：0。

脚本保留 `0.1.0` 的四个应用镜像 pin 作为应用级回滚点；数据库迁移不向后回滚。

## 适用范围与未重跑项

本报告支持 `v0.1.1` 在 UnoRAG-HK 单机参考拓扑运行，并验证从 `0.1.0` 的原位升级。安全初始化管理员
和首次强制改密由空配置脚本测试、数据库集成测试及路由测试覆盖；现有管理员升级后不会被强制轮换。

本次补丁验收没有重跑 `v0.1.0` 的 29 项完整隔离矩阵、并发容量阶梯、Provider 故障注入、应用回退
前滚或破坏性 restore，因此不以本报告替代对应的
[v0.1.0 基线证据](./2026-08-23-v0.1.0-release-acceptance.md)。它也不证明多区域 active-active、
公网共享多租户 SaaS、任意客户语料或任意客户环境容量；客户生产环境仍须按自身身份、备份、模型、
RPO/RTO 和容量目标执行 Go/No-Go。
