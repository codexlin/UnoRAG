## 产品与风格

UnoRAG 面向希望将内部资料转为可检索、可核对、可溯源知识库的团队，默认私有化部署。
知识库和问答是主体验，可观测性帮助管理者理解运行过程、定位问题和恢复服务；不能把所有用户
都当作调试人员，也不能把产品简化为没有来源和状态的聊天窗口。

设计方向为**证据驱动的专业工作台**：以瑞士式排版、扁平界面和中性材质为基础，运行中心使用
更紧凑的信息布局与逐层下钻。风格判断依据是清楚、可信、可控，不是特效数量。

- 清楚：用户知道资料是否可用、回答依据什么、当前操作是否完成。
- 可信：来源、版本、权限、任务状态及未知信息不含糊，不用动画伪造系统进展。
- 可控：从失败结果能找到阶段、原因、关联请求和实际可用的下一步。
- 一致：共享导航、字体、组件和语义，同一领域概念不在不同页面换名字。

UI/UX Pro Max 的 Productivity Tool、Minimalism & Swiss Style、Data-Dense Dashboard 是参考模式，
不是必须整套照搬的模板。Taste/Unslop 用于排版、层次和细节检查；营销页配方不直接应用于工作台。
演示原型中的数字、模型、阶段和交互只用于验证设计，不能成为生产数据或 API 契约。

## 一套系统，两种密度

| 页面 | 首要任务 | 布局和信息层级 |
|---|---|---|
| 智能问答 | 阅读答案、核对依据 | 稳定阅读列、轻量引用、按需展开原文和链路，不默认固定宽证据栏 |
| 知识库 | 查找文档、理解可用性、操作 | 文档列表为主体；可用性与最近任务分列，筛选靠近列表；保留多文件上传，批量管理不是本轮默认新增能力 |
| 文档详情 | 理解来源与处理结果 | 原文、解析结果、版本历史、处理任务按职责分区；不堆成连续指标卡片 |
| 运行中心 | 发现异常、筛选请求 | 必要趋势与请求列表；按时间、结果、阶段等真实维度下钻 |
| 请求/任务详情 | 定位耗时、错误和重试 | 时间轴/瀑布、阶段详情、错误分类和关联 ID；敏感正文不作为默认诊断信息 |
| 账号与工作区设置 | 完成明确配置 | 分组表单、字段级校验、保存与权限反馈，不使用监控台密度 |

问答和原文阅读采用舒适密度；文档台账、请求列表与阶段明细采用标准或紧凑密度。紧凑不是缩小正文，
而是减少重复标签和无效留白。全站不是“同一张仪表盘换标题”。

### 全局结构

- 桌面保留稳定侧栏与轻量上下文栏，主要内容使用可伸缩轨道；不按预览截图写死应用总宽度。
- 问答正文可限制阅读宽度，文档表格和链路按可用空间展开。标题不在多层大字号区域重复出现。
- 导航保留知识库、问答、运行中心等真实目的地；工作区代表内部治理范围，不另称“资料空间”。
- 详情使用有明确返回路径的页面、抽屉或内联展开；选择由上下文和信息量决定，不层层弹窗。
- 手机端简化导航和表格列，保留状态与关键动作；长原文和链路详情进入独立阅读区域，不能缩小整张桌面布局。
- 使用真实容器断点适配侧栏和分栏；允许技术表格在必要时局部横向滚动，但正文与应用本身不得溢出。

### 证据关联

核心工作流是：**答案 → 引用 → 原文位置 → 生效版本 → 本次执行链路**。

1. 引用编号在同一回答中稳定，并指向实际授权来源，不能仅因排序变化重新编号。
2. 点击引用后展示对应文档、页码/行组/章节和版本；没有页码时展示真实定位，不编造页号。
3. 高亮实际支持结论的原文，保留必要上下文；无法定位时明确说明，不在无关句子上补高亮。
4. 长文档定位只在用户主动查看来源时滚动；切换会话、关闭来源后焦点可回到原触发点。
5. 链路入口关联真实 request/job 标识；没有记录时显示不可用，不以示例数据补齐。
6. 权限失效时按后端授权结果处理，不在浏览器缓存或预加载中保留另一个工作区的证据。

历史回答必须核对**该次回答实际使用的来源版本**，不能在文档更新后将旧引用静默替换成当前生效版。
当前生效状态和历史来源状态分别说明；不可读取的来源按现有授权边界处理。

## 核心页面定稿

### 知识库：保留治理能力，重排主次

已选定第一种“独立知识库侧栏”：桌面为“可折叠全局导航 + 208–224px 可搜索库列表 + 文档工作区”。
全局导航首次默认图标栏，可展开并保留浏览器侧栏 Cookie；知识库导航可独立临时收起，保留搜索和当前选择。
手机使用可搜索库选择器，不将整列库列表堆到文档上方。一个库不需要搜索步骤，多个库保留明确的搜索/切换入口。
当前库名、可用文档数和状态就近显示，建库入口位于库选择区域而不是挤入文档操作菜单。

本地已接入基础主题、圆角、导航、库列表、最近任务筛选、逐文件提交结果和分区文档详情，尚未发布。
本轮仍使用已有接口，没有新增 active-version 列表摘要：台账统计和筛选只描述最近任务，生效与目标
版本关系在详情读取现有版本接口后展示。下述列表双状态、数字版本分列与独立可用性筛选仍是后续目标，
不能由最近任务或 `document.status` 推断；“任务完成”计数也不代表全部当前可检索版本数。

页面自上而下的结构：

1. **库页头**：库名/选择器、短描述、可检索/总文档数；上传为主操作，开始提问为次操作，库编辑/删除放设置菜单。
2. **必要提示**：解析策略变化且需要重索引、库不可用、操作错误等；常态下不铺技术策略徽标和大面积统计区。
3. **检索工具栏**：文档名/原文件名搜索、最近任务快捷视图、独立的可用性筛选；计数与范围清楚，不堆两套重复统计。
4. **文档列表**：名称、可用性/生效版本信息、最近处理任务、更新时间、更多操作。大小/格式为次级信息，Chunks 和解析器下沉详情。
5. **上传结果区**：本次多文件提交的逐文件结果及进入已有任务详情的入口；不只保留首个错误或一条 Toast。

显示名与原文件名不同才补充两者关系；长名字允许受控换行并可查看全文，不能让相似文件名全部被截成相同前缀。
不把“原文已保留”称为“原文已预览”；本轮保留现有下载/来源片段能力，不承诺新的完整 PDF 阅读器。

#### 两个状态维度

“现在能否用于问答”与“最近一次处理任务怎么样”分别呈现。示例：

| 情况 | 可用性 | 最近处理任务 | 关键动作 |
|---|---|---|---|
| 首次上传等待解析 | 暂不可检索 | 排队/解析中 | 查看处理，允许时取消 |
| 已有版本，新版正在入库 | 旧版仍可用 | 新版向量化中 | 查看处理，允许时取消 |
| 已有版本，新版失败 | 旧版仍可用 | 更新失败 | 查看原因，符合条件时重试 |
| 首次入库失败 | 暂不可检索 | 解析失败 | 查看原因，符合条件时重试/替换 |
| 新版已激活 | 新版可用 | 已完成 | 查看、提问、下载等 |
| ACL 已保存等待投影 | 按实际授权/投影状态说明 | 权限投影中或等待当前入库 | 查看状态，不把“已保存”当作“已投影” |

“全部 / 处理中 / 需处理”是对最近任务的快捷视图；“可检索 / 暂不可检索”属于独立筛选。
两维可能交叉，不能将这些计数相加冒充文档总数；取消、dead、删除中、解析降级等按真实状态处理，
不统一映射成失败或就绪。没有活动任务不自动等于“已完成”。

#### 列表数据边界

当前 `ApiDocument` 包含状态、版本/generation 标识与最近任务信息，但没有直接提供可用版本的数字序号；
数字 `version` 与 `is_active` 在版本历史接口中。列表重构不得把 UUID 截断当 `v3`，也不得逐行请求
完整版本历史形成 N+1；先显示可信的可用性，打开详情时读取现有历史。若列表确需数字版本，另行审查
有界的汇总投影和测试，再启用该列，不属于颜色/排版修改的隐含内容。

同样，页数、上传字节进度和批量生命周期进度只能在真实接口提供时展示；没有字段就省略或显示未知，
不继承演示样板的页数和百分比。当前名称搜索是已加载文档内的过滤，不能标成“全文检索”或全量服务端搜索。
首次读取列表时显示加载状态，未读到数据前统计为未知；读取失败不显示“尚无文档”，提供就地重试。
后台刷新保留已取得的列表，不在每次轮询时清空内容或重放入场动画。

当前多文件结果只记录本次提交：逐文件显示提交中、已接受、已就绪或提交失败及响应耗时，不把接受
任务等同于完成索引。关闭结果不取消后台任务；切库期间返回的结果仍归原知识库，返回原库可继续查看。
任务完成与失败以台账和详情的实际任务记录为准，不用模拟进度覆盖提交结果。当前结果仅保留在本页内存，
不是持久化上传历史；刷新页面后通过文档和任务记录追踪。

#### 文档详情与操作

点击文档名打开详情，保持列表的搜索、选择和滚动位置；手机进入全屏详情，不在表格下面插入整段长诊断。
抽屉内容按“概览 / 版本 / 处理记录”组织，标签仅在切换确实减少负担时使用；长解析报告采用折叠分区。

- 概览先回答可用性、最近任务与原文件是否保留；失败但旧版服务的情况在顶部一句话说明。
- 版本展示真实 `active`/`desired` 关系，并用可理解中文辅助；不将 desired 直接称为已发布版，不新增恢复旧版操作。
- 处理记录保留阶段瀑布、Provider 等待/轮询、尝试次数与错误码；没有历史任务列表时不伪造列表或重试历史。
- 谁可见、替换、重索引、取消、重试、下载、删除继续由现有 `resolveDocActions`/capability 和后端授权控制。
  高频查看靠近文档名；危险操作分组并保留确认。不能仅为凑齐按钮而开放不可用动作。
- 任务详情中的重试/取消入口可复用现有动作，但不新增第二套请求逻辑；更改权限后继续区分保存与检索投影。

#### 上传与返回路径

多文件选择/提交沿用现有上传能力。结果区分别列出“提交中 / 已接受 / 提交失败”，已接受不等于索引完成；
进一步阶段状态使用已有任务订阅/轮询。关闭结果区不取消后台任务；刷新后能恢复哪些状态取决于已有服务端记录，
不能承诺恢复未持久化的本地传输进度。支持逐项排查及现有任务重试，不借此新增全量批量写接口。

选库、查看文档、返回列表应保持上下文；可分享的库/文档深链接属于目标交互增强，当前本地选择状态不算已经支持。
新增 URL 状态时只放不敏感标识，使用现有授权读取，处理不存在/无权限/已删除的对象，避免状态修复导致越权或自动串库。

### 问答与会话历史：不丢失现有流程

本地第二批已调整问答阅读区、来源片段面板和请求链路抽屉；第三批已接入会话历史的独立导航与阅读区，均尚未发布。
历史页按日期分组，标题搜索和知识库筛选只作用于当前已加载的最多 40 个会话，不冒充全库搜索或完整分页。
窄屏在列表与详情之间切换，返回保留原选择与筛选；继续对话保留原 thread，逐轮引用仍使用回答时的来源版本。
请求失败或无权访问时清空上一会话的正文和引用，并保留重新加载入口；不增加后端不支持的删除操作。
正文使用约 768px 的最大阅读列、16px 字号和 1.85 行高，不再为每轮答案加卡片外壳。
发送问题不自动弹出引用；宽度至少 1280px 时按需分栏，更窄的视口使用抽屉，关闭后恢复引用触发点焦点。
只改呈现和局部交互，不改 Ask SSE reducer、生命周期或授权检查。
同一轮本地 UI ID 在流完成前后保持不变，Markdown renderer 的组件身份也保持稳定，避免完成时
重新挂载正文、清空选择或丢失焦点。若 Markdown 结构校正确实替换引用节点，按同轮、同来源标识恢复
当前引用按钮；对象已不存在时回到提问输入，不跳到另一个会话或不同来源。

- 保留知识库选择、健康/就绪提示、停止生成、临时会话归档、已归档会话续聊和来源面板。
- 库为空、无可用证据、拒答、Provider 错误、取消、归档失败分别表达；不是统一显示“没有答案”。
- 正文优先，引用按需查看。诊断抽屉可展示真实用量和降级原因，不在每轮回答默认铺开算法参数。
- 切库开始新会话，旧流不污染新会话；停止时保留实际收到的内容，不能为了退场动画继续接收旧回调。
- 来源高亮由实际片段与定位支持；“谁可读历史”与“哪些历史可继续给模型使用”保持既有独立检查。
- 来源详情明确标为“来源片段”，不能把召回 Chunk 称作完整原文。回答所用版本只读取引用快照中的
  `document_version_id`，缺失显示未记录，不查询当前 active 来替换历史来源，不推断数字版本。
- 表格来源的行组定位在界面按 1 起算，引用快照仍保留 0 起算的原始行号；展开时优先显示快照中的表头与行，
  完整且列数一致的管道表可作为兼容来源。使用可键盘横向滚动的紧凑语义表格，无法可靠解析时保留原文。
- 检索分数按返回值展示，不将 BM25/RRF 映射成无依据的概率条；算法诊断默认收起。
- 流中断时显示错误并保留已收到的正文和来源；拒答不统一标成“无命中”或“未调用生成”，调用与用量由真实诊断记录说明。
- 会话历史仍是独立入口；桌面可用会话列表，手机先列表后详情，继续对话回到对应 thread，不创建相似的新会话冒充续聊。

## 视觉系统

### 配色与材质

工作台不被 Logo 或青绿色约束，内置 tweakcn 的 **Vercel（默认）、Claude、Violet Bloom**
三套主题，不再保留临时的中性/蓝色选项。主题与“浅色 / 深色 / 跟随系统”、圆角分别选择。
不是只替换主色：背景、文字、浮层、侧栏、图表和阴影跟随预设；失败、成功、告警仍保持产品语义。
Vercel 是高对比黑白，Claude 是暖白与陶土强调，Violet Bloom 是中性表面与紫色强调。

主题已在本地源码接入，尚未随版本发布，也不表示全站页面重构完成。官方注册表 JSON 快照保留在
`src/styles/themes/`；`src/styles/themes.css` 由脚本生成，产品诊断色和几何规则在
`src/app/globals.css`。组件使用语义 Token，不散落原始色值。

| 产品语义 | 浅色参考 | 深色参考 | 用途 |
|---|---|---|---|
| 有效引用/交互 | 主题强调色阶 | 主题强调色阶 | `evidence`，与成功状态分离 |
| 成功 | `#28734C` | `#8DCDAB` | `cite` 历史 Token，不随主题改变 |
| 等待/降级 | `#795014` / `#FCF3DF` | `#EDCB91` / `#352B1C` | 告警文字/浅底 |
| 失败/危险操作 | `#B42318` | `#F1A2A2` | 不使用预设可能为黑色的 destructive |

成功、等待/降级、失败另用语义绿、琥珀、红，且同时显示文字或图标；主题强调色不表示“成功”。
引用使用 `evidence`，成功状态保留 `cite` 历史 Token；告警使用 `warning` / `warning-foreground`，
菜单悬停等通用状态使用 `accent`，不混用。旧页面的局部强调随逐页重构迁移，不将全站换肤误称为全站语义整改。
所有文字与实际背景至少满足常规文字 4.5:1，大字和必要非文字 UI 至少 3:1；颜色组合须在真实
组件状态中测量，不能因为列入表格就视为已通过对比度检查。

- 不使用常驻模糊光晕、离散光球、渐变光斑、外发光、粒子背景或大面积玻璃效果。
- 层次来自中性背景、间距和细分隔线，不给每个区块加浮动卡片；不在卡片里继续套卡片。
- 菜单、弹窗等真正浮层可有轻微中性阴影。弹窗背景允许适度变暗和轻微模糊，但不能损害性能和焦点辨识。
- 明暗继续由 `next-themes` 管理，沿用 `unorag-theme`；配色和圆角使用版本化的 `unorag-appearance-v1`。
  仅保存当前浏览器外观偏好，不写工作区业务配置，不代表跨设备账号同步。刷新前置恢复、同源标签页同步；
  无效值回退默认，存储不可用时保留本页操作能力，不影响登录和业务。
- 对外品牌页面可更有表现力，但不借此在日常工作台加入装饰动效；旧 Logo 不构成新配色的约束。

### 主题扩展与圆角

外观入口位于顶部调色板按钮及登录页。圆角使用 **0–8px 滑块、0.5px 步进、默认 4px**，
拖动时即时应用；同时提供数值输入，失焦或 Enter 时提交，空值恢复当前值，越界值限制到有效范围。
滑块支持方向键及 Home/End，数值输入提供不依赖拖拽的操作方式。旧三档偏好按 0/4/8px 迁移。
由根 `--radius` 映射控件和浮层，最大常规圆角不超过 8px；不随主题覆盖圆角、间距、控件尺寸、
状态点/头像等必要圆形，也不覆盖有明确语义的 `rounded-none`。不支持任意 CSS 或远程主题注入。

主题标识、名称集中在 `src/lib/appearance.ts`；预览与页面共用生成的色阶，不手抄一套缩略图颜色。
生成的 CSS 按根 `data-color-theme` 和局部 `data-theme-preview` 定义，
明暗仍使用 `.dark`。来源为 `https://tweakcn.com/r/themes/{vercel,claude,violet-bloom}.json`，
源码及许可说明保留在仓库，不在运行时执行 `shadcn add` 或加载远程主题；CLI 直接添加只会覆写当前
一套全局变量，不能代替产品的多预设切换。更新快照后运行 `pnpm themes:generate`，
`pnpm themes:check` 与测试防止源数据/生成物漂移。官方 tracking、spacing、radius 不导入；
保持字距 0、4px 间距体系和用户圆角。无效或旧临时主题标识回退 Vercel，仍保留有效圆角。
`overrides.json` 明确记录可访问性调整：Claude 浅色次要文字/陶土强调加深、深色强调提亮并使用深色按钮文字，
引用另用更亮的同色阶，保证引用悬停/高亮浅底仍可读；
Violet Bloom 深色强调提亮并使用深色按钮文字、侧栏选中文字提亮，浅色 accent 文字略加深。
保留原始 JSON 不改写，避免把产品适配误称为官方原值；真实浏览器测量关键文字/背景组合至少 4.5:1。
新增预设同时提供浅深色、保持诊断语义与阶段对应关系，并跑对比度和浏览器组合测试；不复制页面，
不引入另一套 Theme Provider、组件库或主题编辑器。bootstrap 与运行时解析共享主题白名单、
圆角数值范围、步进和旧值映射；只接受归一化的有限数值，不将存储内容直接作为 CSS。

### 主操作与主题色

`Button` 的默认 variant 即 primary，不需要另造 `primary` variant 或在业务组件写颜色值。
主题主色表达操作优先级，不表达成功、失败，也不要求每个可点击对象都填充主色。

| 操作或状态 | 样式规则 |
|---|---|
| 新建知识库 / 空态建库 | 默认 primary；桌面侧栏与手机选择器保持一致 |
| 上传文档 / 空库上传 | 文档工作区的 primary；与库选择区域的建库属于不同任务区域 |
| 创建、保存、确认权限等表单提交 | 当前弹窗或表单的 primary；取消使用 outline/ghost |
| 发送问题、邀请成员、创建密钥、保存配置 | 各自任务区域的 primary，保留请求中与禁用反馈 |
| 开始提问、刷新、搜索筛选、设置、下载、复制、查看详情 | outline/ghost 或正文链接，不与当前提交动作争夺强调 |
| 已选知识库 | 轻量主题提示与 `aria-current`，不是整行实心主色；Hover 仍使用通用 accent |
| 删除、撤销等危险操作 | destructive，并保留现有确认与授权，不改成主题色 |
| 状态、告警、有效证据 | 使用各自语义 Token；不用 primary 冒充“已就绪” |

每个明确任务区域保留一个主要动作；同一页面允许独立的库选择区域和文档区域各有一个主要动作。
菜单中的“新建工作区”等仍遵循菜单样式，真正提交表单时才使用 primary，不给所有菜单项涂主色。

### 字体、间距与组件

- 字体随主题内置：Vercel 使用自托管 Geist/Geist Mono，Claude 使用系统无衬线/等宽，
  Violet Bloom 使用自托管 Plus Jakarta Sans/IBM Plex Mono；中文使用系统字体回退。
  不向 Google Fonts 或 tweakcn 发起运行时请求，不为未使用的衬线角色另增字体下载。
- 问答与原文正文以 16px 为基准、行高约 1.7–1.9；操作界面以 14px 为基准，元信息不低于 12px。
- 紧凑面板标题约 16–20px，页面标题约 24px；优先 400/500 字重，少量 600 强调，不使用英雄级标题填后台。
- 等宽字体只用于 ID、代码和需要对齐的技术数据；不把整页中文、导航和说明排成等宽字体。
- 现有 Fraunces 仅作为少量品牌/对外展示的候选，不用于工作台常规标题。字距为 0，字号不随视口宽度连续缩放。
- 使用 4px 间距体系；页边距约 24–32px，组件内部约 8–16px；同类行和图标按钮保持稳定尺寸。
- 常规控件圆角由用户预设控制，默认 4px，必要卡片和弹窗不超过 8px；页面分区本身不需要圆角外壳。
- 使用 Lucide 图标，常规 16/18px、一致描边；图标按钮提供可访问名称，必要时提供 Tooltip。
- 模式使用分段/单选控件，开关用于二元设置，数字使用输入/步进器；不把所有设置做成带文字的圆角按钮。
- 空态显示当前对象与可执行动作；不写欢迎语、大段功能介绍、快捷键教学或装饰性的英文大写眉题。

不是整套字号或界面密度规范。本次实查其默认 Cards 预览：普通标签/说明为 14/20px，面板标题为
18/28px，突出金额为 30/36px；后者不适合直接搬到知识库管理页标题。字体列表包含 Geist、
Plus Jakarta Sans 等，但“热门”不等于适合所有语言。产品继续沿用三主题内置字体，不额外叠加 Inter；
中文主要依赖系统回退，必须结合中文字重、行高和对比度验收，而不能仅凭拉丁字体名称判断完成。

## 数据和状态表达

界面必须忠实表达系统事实，动效不能替代这些规则。

| 场景 | 必须表达 | 禁止表达 |
|---|---|---|
| 文档替换失败 | 本次任务失败；旧版本仍可用时同时显示其版本 | 整份文档“不可用”，或只保留一个混杂的状态徽标 |
| 上传与后台处理 | 文件传输、排队、解析、切分、向量化、索引/激活分别表达 | 上传 100% 就称“已索引” |
| 未知进度 | 当前已确认阶段、已等待时间，必要时不定进度 | 根据时间模拟百分比或自动走向成功 |
| 阶段耗时 | 实际起止与计时口径；并行、重试不强行求和 | 将所有子耗时相加冒充总耗时 |
| 首 Token | 明确从请求开始或模型调用开始计时 | 把模型调用总耗时当首 Token 耗时 |
| Token/成本 | 实际返回的用量、缺失状态与估算口径 | 缺失显示 0，或没有价格依据却显示实际费用 |
| Rerank | 配置、就绪、实际执行/跳过/降级分别呈现 | 将“功能可用”当作本次“已执行” |
| 错误 | 阶段、分类、可理解原因、关联 ID、是否可重试 | 未经证据把超时归因到用户、网络或服务商内部 |
| 历史数据 | 保留未知、未采集、未执行的区别 | 给旧记录补示例模型、阶段或统计 |

错误保留在相关页面/详情内，不只依赖短暂 Toast。诊断页默认 metadata-only，问题/回答正文、Prompt、
检索块和凭据不得为“展示完整链路”而新增采集；跳转回答或原文须走已有授权入口。
原生诊断不依赖 Langfuse/Grafana 在线。外部观测不可用不能使基本查看和产品操作失效。

## 反馈与动效

动效解释操作和状态变化，不是背景装饰。核心标准是：**操作有回应、变化有原因、等待可理解**。

### 统一节奏

| 动效类型 | 建议时长 | 规则 |
|---|---|---|
| Hover、按下、轻量控件 | 120–160ms | 颜色/透明度变化；按下可有极小位移，不改变布局和命中范围 |
| 引用、局部详情展开 | 160–200ms | 一次短淡入或小幅位移；已有内容不反复入场 |
| 抽屉、菜单、弹窗 | 180–240ms | 方向与空间关系一致；退出可略快，不阻塞关闭和焦点恢复 |
| 复杂详情切换 | 最多约 280ms | 确有必要再用；不为等待数据而人为延长 |

实现时集中维护节奏和缓动，不在每个页面发明不同弹簧和延时。默认采用平稳 ease-out，避免回弹、
大幅缩放、翻转、晃动及 `transition: all`。优先 `transform`、`opacity` 和低成本颜色过渡；不对长列表
逐行做 layout 动画，也不持续动画 `width`、`height`、位置、阴影或大面积模糊。

### 按场景应用

- 按钮和列表：Hover/按下有反馈；请求中保持按钮宽度和文字含义，避免重复写入，不用全页锁定替代局部等待。
- 引用：点击后展开对应原文并一次性高亮；原文不逐字出现，不抢走用户继续阅读的位置。
- 抽屉：方向稳定，关闭或按 Escape 后恢复合理焦点。优先沿用 Base UI 的语义、Portal 和焦点生命周期。
- 上传：及时展示选中文件、传输和任务提交状态；处理进度以真实阶段事件为准，完成提示以服务端终态为准。
- 列表：后台轮询只更新变化项，保留滚动、选择和键盘焦点；不因刷新闪屏或自动重新排列正在操作的行。
- 流式回答：继续使用有界增量渲染，不对每个 Token/字符增加 Motion 动画；用户查看历史时不强制滚到底部。
- 瀑布：Hover/键盘聚焦关联阶段，点击查看明细；历史请求不循环播放。实时阶段仅在真实执行期间显示等待反馈。
- 复制与保存：成功后给轻量确认；不要每次正常后台刷新都弹 Toast。
- 错误与重试：错误留在上下文中，重试展示真实新尝试；不在失败后播放成功动画，不通过抖动表达唯一错误信息。
- Skeleton：保持最终布局尺寸，短暂且有用；不能在轮询中反复替换已知数据。

### 减少动态效果与可访问性

- CSS 尊重 `prefers-reduced-motion`；Motion 使用 `MotionConfig reducedMotion="user"` 并在必要场景使用
  `useReducedMotion`。该配置不是全部动效的自动验收，仍须检查 CSS、spinner 和自定义实现。
- 减少动态效果时关闭空间位移、自动滚动和循环装饰；可直接切换或保留短淡入，状态文字和反馈仍可见。
- 动画关闭、JavaScript 降级或低性能设备上，内容与功能不得依赖“动画完成回调”才能出现。
- 所有核心操作可键盘完成，焦点清楚且不被浮层遮挡；触屏有效点击区域至少约 44×44px，互不重叠。
- 错误使用合适的 `role="alert"`/关联说明，异步结果使用克制的 `aria-live`；不让屏幕阅读器逐 Token 播报。

### 基础控件优先 shadcn

`components.json` 已选择 `base-nova`。新增基础控件先查官方 registry，再以源码方式纳入；
不再在业务页面仿写已有的 Slider、RadioGroup、Checkbox、Switch、Select、Dialog、Tabs 等交互原语。
本地源码不是“另造一套库”：shadcn 本身就是源码分发，产品只做有记录的主题、触屏、字距、圆角和无障碍适配。
不能通过一键覆盖已经定制的全局 CSS、Button 或 Dialog 来安装新组件。

- Slider/RadioGroup：外观选择与圆角；保留即时反馈、精确输入、键盘和持久化。
- Checkbox：集合选择，如文档可见成员；Switch：即时二元设置，如自动刷新、通知开关、对话记忆。
- Select：普通表单与筛选统一采用官方 Base UI 版本的标准组合，使用 `items`、受控 `value` 和
  `onValueChange`；不保留 NativeSelect 或模拟原生事件的兼容层。Trigger 保留标签与禁用状态。
  长选项允许换行，菜单受可用视口约束，触屏目标至少约 44px；不改为另一套组件 API。
  大量选项和搜索继续用已有 Combobox；不另造 AppSelect 包装器。
- Input/Button/Label/Dialog 等继续复用已有本地组件；不是把 HTML 标签逐个包一层就算组件化。
- 原生文件输入、灾难性全局错误页的最小恢复按钮，以及有独立排版/焦点契约的行内引用属于合理例外。
  文档台账、任务瀑布和证据卡是领域组合，不是 shadcn 可以取代的业务能力；内部基础交互仍优先统一。

官方源码来源及 MIT 许可保留在 `NOTICE`；基础组件变更需检查受控值、禁用、表单提交、标签与焦点。
Base UI 的隐藏表单输入不等于第二份可操作控件；测试通过可见的 `radio` / `checkbox` / `switch` 角色定位。

### 问答复用官方 AI Elements

采用 [shadcn AI Elements Chat](https://ui.shadcn.com/docs/ai-elements/base/chat) 的 Base UI 组合，
不引入另一套聊天框架或替换现有 SSE 状态机。组件源码与普通控件一同置于 `src/components/ui/`。

| 官方组件 | 当前用法与边界 |
|---|---|
| Message / Bubble / MessageFooter | 组织用户问题、回答及动作；回答保留无框阅读列，不将长答案压进气泡 |
| MessageScroller | 每轮作为直接子 Item，用稳定 turn ID 定位；空态不作为消息。恢复的历史不标新消息锚点，新提问才定位到新轮；流式跟随和手动阅读由官方原语管理 |
| Prompt Input / InputGroup | 组合受控输入、发送和停止；保留输入法合成、Shift+Enter、服务可用性和取消行为 |
| Sources / Inline Citation | Sources 使用 TraceCollapsible 默认折叠，保留逐条依据而不按文件名/URL 合并。编号引用使用 HoverCard + Button 提供快照预览；点击/键盘/触屏继续打开完整来源面板，保留版本、定位与焦点回返 |
| Suggestion | 推荐问题使用官方 Button 组合，仍仅填入输入框，不自动发问；不暗示不存在的内置知识 |
| Reasoning / Chain of Thought / Tool / Agent | 当前接口未提供对应内容，不启用；不能将检索进度或阶段耗时伪装成模型思考 |
| Trace / StackTrace | Trace 组织已记录的阶段详情、状态和诊断字段；保留现有瀑布、错误分类、Token 用量与请求 ID，不由前端模拟实时步骤，也不对用户新增服务端堆栈 |
| Attachments / Model Selector / Approval | 有对应业务契约后再按需接入，不因组件存在就新增功能 |

MarkdownAnswer 继续负责现有安全链接、引用绑定和渐进代码高亮，不在这轮替换 Markdown 引擎。
`@shadcn/react` 固定版本用于消息滚动，无运行时 registry/CDN 请求。滚动按钮遵守 reduced-motion，
浏览器测试覆盖生成中停止、旧流竞态、切库、引用焦点、长文/代码和阅读位置。
用户主动选择的来源按 `turnId + sourceId` 定位：同轮完成只刷新对应快照，其他轮的流事件不覆盖
当前选择，高亮与回焦也使用同一双键，不因跨轮复用同一 chunk ID 而同时选中。
输入框高度随受控值同步，覆盖清空、切库和选择示例，而不只监听手动输入事件。
引用悬停预览只读取当前回答的授权快照，展示标题、定位、片段及回答所用版本；不发起额外版本/文档查询，
不打开完整来源面板或修改当前来源选择。完整内容仍通过点击/键盘/触屏访问；预览不是唯一读取入口。
预览高度不超过可用屏幕空间，长内容或文字放大时内部滚动；来源标题可换行，顶部库选择器空间不足时换行。
Inline Citation 的稳定组件身份在流更新与完成时保留；完整来源打开时收起预览，不能叠加遮挡抽屉。
问号说明采用 shadcn Popover 的 `openOnHover` Infotip，鼠标可悬浮、键盘/触屏可点击；
已有动作的简短名称使用 Tooltip。关键权限、失败和外传提示仍在页面内可见。

### 装饰型组件来源

[Magic UI](https://magicui.design/docs/components)、[Aceternity UI](https://ui.aceternity.com/components)

## 代码组织与实施顺序

保持现有目录边界，详见 [DEVELOPMENT](./DEVELOPMENT.md#代码放在哪里)：

2. `src/components/ui/`：无业务语义的 Button、Dialog、Sheet、Tooltip 等；同一属性只由一个动画机制控制。
3. `src/components/app/`：共享来源、状态、模型用量、瀑布等产品展示；领域交互继续按功能就近组织。
4. Ask SSE、TanStack Query、授权与版本服务保持现有职责；UI 动画不得新增第二份任务、权限或激活状态事实源。

这不是创建通用动画框架、全量列表 schema 或新的 package 的理由。简单 CSS 先行；只有真实重复且
