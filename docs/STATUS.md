# UnoRAG 当前状态

> 更新日期：2026-11-12。本文只维护当前成熟度、已知限制和下一步；架构细节见 [ARCHITECTURE](./ARCHITECTURE.md)，逐版结果见 [验收索引](./evidence/README.md)。

## 当前结论

UnoRAG 是 Apache-2.0 开源、TypeScript-only 的私有化知识库产品，已超过 Demo，具备受控试点和
小规模私有化交付基础；不是对任意客户环境的 production-ready 或安全认证。默认一位客户一套独立实例，
Workspace 用于企业内部治理，不是公网共享多租户 SaaS。

当前公开稳定版仍为 [v0.2.8](https://github.com/codexlin/UnoRAG/releases/tag/v0.2.8)。
香港参考实例 `https://unorag.unobyte.dev` 已升级至镜像版本 `0.2.11`（提交 `288677a`），
包含解析总预算终止、超时诊断及评测就绪检查。签名交付、升级冒烟、7/7 新文件入库和浏览器检查通过，
但三轮机器结果 **122/126、NO-GO**：3 条为季度同义表达的词面差异，另有 1 次真实的冲突摘录校验故障。
**部署成功不等于质量放行**，尚未创建正式 `v0.2.11` tag/Release，也未更新公开稳定版。
v0.2.9/v0.2.10 的失败记录保留。收件策略仍在应用中配置，传输凭据仅保存在服务器私有配置。
后续源码或文档提交不自动改变已部署版本。配置与安全边界见 [运维指南](./OPERATIONS.md#账号邮件)。

## 已知限制

- [#231](https://github.com/codexlin/UnoRAG/issues/231)：短编号修复不代表消除了全部 Judge 故障。
  本轮语料完整就绪，第三轮仍出现 `conflict_provenance / conflict_quote_mismatch`，安全拒答而未生成答案。
  已定位到冲突摘录与原文的匹配校验，不是入库超时；未保存原模型摘录，不能断言具体字符差异或完整根因。
- [#237](https://github.com/codexlin/UnoRAG/issues/237)：季度事实的有限等价表达尚需版本化评测契约。
  本轮 3 条 `Q2`/“第二季度”差异经代理复核有来源支持，但原机器 FAIL 保留，不折算成自动 PASS。
- [#193](https://github.com/codexlin/UnoRAG/issues/193)：历史单次 Qdrant 故障根因未知，等待新的关联证据。
- [#202](https://github.com/codexlin/UnoRAG/issues/202)：可选离线 Ragas/DiskCache advisory；该 Python 环境不在四个产品镜像内。
- COS sidecar 只有对象引用，不是文件内容备份；尚未据此证明对象误删或桶级恢复能力。
- [#229](https://github.com/codexlin/UnoRAG/issues/229)：总预算耗尽不再自动重提 staging，补丁已部署。
  本轮 7/7 完成，四份 PDF 的客户端 Provider 等待约 9–19 秒；未提高并发、延长预算或更换路线。
  这不解释历史长等待的服务商内部根因，也不证明未来延迟保证或跨重启任务去重；原失败报告不改写。
- 账号邮件使用有界请求/Next `after`，不是持久化账号邮件队列；进程中断可能需要重新申请。告警投递另有持久化重试。
- 冲突核验只覆盖事实/追问的已授权召回证据，不是全库矛盾检测；表格、比较、汇总和目录不运行这一步。
- 完整标题目录有界，文档身份目录超过 500 份授权文档会失败关闭；BM25 适用于小中型语料，不是百万级容量承诺。
- 图文 PDF 目前证明正文/图注恢复，不代表 ChartIR 或独立图表数值理解。
- 没有可交付 OIDC/SSO、SCIM/用户组管理 UI、稳定公共文档生命周期 API；Helm 仍是 starter。
- PostgreSQL 使用作用域查询、约束及分离运行角色，未启用 RLS；模型并发门不是跨副本 Provider 配额管理。

## 下一步

1. **先收口本轮真实失败**：处理 #231 的冲突摘录输出契约与可用性，不降低原文校验；单独审查 #237 的季度等价表达，保留旧机器结果。再用新候选完整复验，当前不放行 v0.2.11；#229 继续保留上游等待观察。
2. **真实业务试点**：质量放行后使用获授权的客户材料和原始问题，留出未参与调优的验收题，记录正确性、引用与实际解决率。
3. **独立上手验证**：让未参与开发的人只看文档完成安装、配置、上传、排错和升级；补齐客户对象存储恢复方案。
4. **稳定维护**：以真实失败样本扩充回归，观察延迟、队列与成本；当前文档只维护一份事实，不用重试成功替代根因分析。

暂不推进公网 SaaS 计费、完整 Ops Stack 默认部署、OIDC/SSO、ChartIR、万行表 SQL 引擎或 monorepo。
这些能力按真实需求与证据排序，不为了目录整齐或功能数量启动新架构。
