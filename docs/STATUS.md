# UnoRAG 当前状态

> 更新日期：2026-11-10。本文只维护当前成熟度、已知限制和下一步；架构细节见 [ARCHITECTURE](./ARCHITECTURE.md)，逐版结果见 [验收索引](./evidence/README.md)。

## 当前结论

UnoRAG 是 Apache-2.0 开源、TypeScript-only 的私有化知识库产品，已超过 Demo，具备受控试点和
小规模私有化交付基础；不是对任意客户环境的 production-ready 或安全认证。默认一位客户一套独立实例，
Workspace 用于企业内部治理，不是公网共享多租户 SaaS。

当前稳定版为 [v0.2.8](https://github.com/codexlin/UnoRAG/releases/tag/v0.2.8)，绑定 `0d52120`。
香港参考实例 `https://unorag.unobyte.dev` 运行该版本的正式 GHCR 签名镜像。候选和稳定版使用同一源码，
但镜像 digest 不同，验收证据分开记录。后续源码提交不自动成为已部署版本。

当前开发分支另含未发布的工作区邮件通知设置、邀请邮件模板、已有账号邮箱登录和密码找回；
这些变更不代表香港实例已启用真实邮件。配置与安全边界见 [运维指南](./OPERATIONS.md#账号邮件)。

## 已知限制

- [#193](https://github.com/codexlin/UnoRAG/issues/193)：历史单次 Qdrant 故障根因未知，等待新的关联证据。
- [#202](https://github.com/codexlin/UnoRAG/issues/202)：可选离线 Ragas/DiskCache advisory；该 Python 环境不在四个产品镜像内。
- COS sidecar 只有对象引用，不是文件内容备份；尚未据此证明对象误删或桶级恢复能力。
- 本轮验收中外部 MinerU 轮询出现短时 HTTP 500，已有重试恢复；复杂 PDF 入库耗时受 Provider 波动影响。
- 冲突核验只覆盖事实/追问的已授权召回证据，不是全库矛盾检测；表格、比较、汇总和目录不运行这一步。
- 完整标题目录有界，文档身份目录超过 500 份授权文档会失败关闭；BM25 适用于小中型语料，不是百万级容量承诺。
- 图文 PDF 目前证明正文/图注恢复，不代表 ChartIR 或独立图表数值理解。
- 没有可交付 OIDC/SSO、SCIM/用户组管理 UI、稳定公共文档生命周期 API；Helm 仍是 starter。
- PostgreSQL 使用作用域查询、约束及分离运行角色，未启用 RLS；模型并发门不是跨副本 Provider 配额管理。

## 下一步

1. **真实业务试点**：使用获授权的客户材料和用户原始问题，留出未参与调优的验收题，记录正确性、引用与实际解决率。
2. **独立上手验证**：让未参与开发的人只看文档完成安装、配置、上传、排错和升级；补齐客户对象存储恢复方案。
3. **稳定维护**：以真实失败样本扩充回归，观察延迟、队列与成本；保留发布门禁，不用重试成功替代根因分析。
4. **仓库可维护性**：当前文档只维护一份事实，旧结论固定链接归档；按功能归拢代码，机械移动与行为变更分开。

暂不推进公网 SaaS 计费、完整 Ops Stack 默认部署、OIDC/SSO、ChartIR、万行表 SQL 引擎或 monorepo。
这些能力按真实需求与证据排序，不为了目录整齐或功能数量启动新架构。
