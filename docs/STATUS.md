# UnoRAG 当前状态

> 更新日期：2026-11-12。本文只维护当前成熟度、已知限制和下一步；架构细节见 [ARCHITECTURE](./ARCHITECTURE.md)，逐版结果见 [验收索引](./evidence/README.md)。

## 当前结论

UnoRAG 是 Apache-2.0 开源、TypeScript-only 的私有化知识库产品，已超过 Demo，具备受控试点和
小规模私有化交付基础；不是对任意客户环境的 production-ready 或安全认证。默认一位客户一套独立实例，
Workspace 用于企业内部治理，不是公网共享多租户 SaaS。

当前公开稳定版仍为 [v0.2.8](https://github.com/codexlin/UnoRAG/releases/tag/v0.2.8)。
香港参考实例 `https://unorag.unobyte.dev` 已升级至 tag `v0.2.10`（绑定 `6e02ab4`）的 GHCR 签名镜像，
包含工作区邮件、账号链接及 Judge 短证据编号/诊断修复。**部署成功不等于验收通过**：本轮 PDF 入库
超出 900 秒批次期限，三轮 87/126，正式 Release 不放行。v0.2.9 的 Judge 失败与草稿状态保留，
不更新公开稳定版。收件策略在应用中配置，传输凭据仅保存在服务器私有配置。
后续源码或文档提交不自动改变已部署版本。配置与安全边界见 [运维指南](./OPERATIONS.md#账号邮件)。

## 已知限制

- [#231](https://github.com/codexlin/UnoRAG/issues/231)：短证据编号和安全诊断已合并/部署，派生核心重放 6/6。
  本轮未出现 Judge `model_error`，但图文 PDF 未及时入库，不能视为原失败场景完整复验或关闭该项。
  历史三个请求的具体中间输出未保存，不能回溯断定每次都由同一原因触发。
- [#193](https://github.com/codexlin/UnoRAG/issues/193)：历史单次 Qdrant 故障根因未知，等待新的关联证据。
- [#202](https://github.com/codexlin/UnoRAG/issues/202)：可选离线 Ragas/DiskCache advisory；该 Python 环境不在四个产品镜像内。
- COS sidecar 只有对象引用，不是文件内容备份；尚未据此证明对象误删或桶级恢复能力。
- [#229](https://github.com/codexlin/UnoRAG/issues/229)：外部 MinerU/302 曾长时间保持 running，仍待上游时序证据；
  本轮跨页表处理约 382 秒，图文 PDF 长等待叠加香港 auto/mineru 单并发队列，超出批次入库期限；
  排队未开始解析不等于该文件自身解析失败。未直接改并发/预算刷绿。
  已修复本地轮询间隔不等于解决上游等待；复用评测工具另已修正，原失败报告不改写。
- 账号邮件使用有界请求/Next `after`，不是持久化账号邮件队列；进程中断可能需要重新申请。告警投递另有持久化重试。
- 冲突核验只覆盖事实/追问的已授权召回证据，不是全库矛盾检测；表格、比较、汇总和目录不运行这一步。
- 完整标题目录有界，文档身份目录超过 500 份授权文档会失败关闭；BM25 适用于小中型语料，不是百万级容量承诺。
- 图文 PDF 目前证明正文/图注恢复，不代表 ChartIR 或独立图表数值理解。
- 没有可交付 OIDC/SSO、SCIM/用户组管理 UI、稳定公共文档生命周期 API；Helm 仍是 starter。
- PostgreSQL 使用作用域查询、约束及分离运行角色，未启用 RLS；模型并发门不是跨副本 Provider 配额管理。
